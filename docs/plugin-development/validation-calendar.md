# 文档实作验证：我的日历

状态：文档实作验证完成，2026-11-04；原生写入授权后的持久化仍需使用者验收，见文末边界。

## 输入与边界

开发输入固定为本目录开发指南、Demo 案例和 mytools-demo 源码，以及用户以下需求。自此实现日历不再查阅宿主内部实现，不复制其他业务插件代码，不新增宿主能力。日历算法使用指南说明的第三方库独立公开接口。发现契约缺项先补指南，再调整实现。

- 左侧周一起始的月视图显示公历、农历、传统节日和节气，右侧是所选日期的待办。
- 支持上一月、下一月、今天；公历/农历年月日跳转，农历闰月与实际天数合法校验。支持公历 1901-01-01 至 2099-12-31；转换结果也必须在范围内。
- 待办支持添加、编辑、完成、删除，预设/自定义标签、状态与标签筛选；月格展示当日待办与数量，可以关闭展示。筛选同时作用于月格和右侧列表，统计注明筛选状态。
- 数据使用 storage.get/set，仅存在当前设备，不申请网络/剪贴板/文件权限；持久化读写失败可见且可重试，不用 localStorage。
- 未提供官方年度放假安排，因此展示端午、春节、国庆等“节日”，不推断调休或补班。
- 不增加提醒、账号、云同步或重复任务；独立窗口与主窗口需要顺序编辑，宿主当前不提供多窗口存储锁。

## 发现并纠正的文档问题

整理前核对公开桥接与实现时发现：旧规范把宿主内部结构化错误写成插件可用错误；普通浏览器并不会自动提供 window.mytools；Demo README 将尚未发布的 0.1.1 当成可安装包；文档索引仍要求“只描述目标”；旧交接的插件数及商店快照描述过时。以上已在开发开始前纠正。

指南补足了存储版本校验、加载前禁用、保存失败重试、离开前持久化、离线依赖交付、实际归档验证和日期/闰月边界。不存在的 API 不写入案例。


## 最终结果

插件位于 plugins/mytools-calendar，独立本地 Git 仓库，版本 0.1.0；没有新增宿主能力、IPC、插件特例或运行时依赖。所有宿主调用仅为开发指南定义的 storage.get/set。第三方农历库固定 lunar-javascript 1.7.7，包内携带未修改浏览器产物和 MIT 许可，SHA-256 在 THIRD_PARTY.md 与测试中核对。

检查结果：

- 日历 Node 测试 16/16 通过：节日/节气、闰月、公农历跳转、日期边界、42 格月历、待办编辑与筛选、HTML 文字显示、读失败重试、写失败保留输入、重开恢复和版本保护。
- Demo 测试 2/2 通过；宿主索引测试 2/2 通过，未发布日历不会形成 npm 安装入口。
- 宿主 pnpm type-check 通过；pnpm lint:frontend 为 0 错误、13 条既有警告。本次不涉及 Rust 修改，没有重跑无关后端测试。
- npm pack / dry-run 通过，运行归档 13 个文件，约 127 KB；不包含测试、node_modules 或用户数据。
- 文档本地相对链接检查通过。新增 AGENTS、项目上下文、指南和案例，Demo README 改正未发布状态；正式推送前新文档的远程链接尚未上线。
- 通过实际 tgz 解包到统一插件根并重新扫描，真实 MyTools 成功识别“我的日历”；嵌入和分离窗口均载入，无插件错误面板。
- 原生分离窗口确认左侧月历、右侧待办；日期跳转弹窗成功从公历切换到对应农历（2026-11-04 ↔ 农历 2026 年九月廿六）并跳转返回。系统深色主题已目视检查。

实机发现默认小窗口的响应式断点过早使待办排到月历下方，已把上下布局断点调整至 600px，并补充矮窗口样式。也发现当前开发者界面实际提供的是“安装插件包（.zip / .tgz）”、打开插件目录和重新扫描，指南与案例已改为这套可操作流程，不再要求寻找不存在的“安装本地目录”按钮。

验证边界：自动化以模拟桥接验证保存/重开/失败恢复；原生只读取新插件的空存储，没有自动接受存储写权限、没有创建用户待办。首次保存时按宿主提示授权后，仍应手动验证一次关闭/重新打开后的保存结果。浅色主题和真正小屏窗口的最终观感尚未逐一人工验收。节日并非官方年度放假/补班表，多窗口同时编辑没有锁。

结论：这套文档足以独立实现并在宿主加载一个有离线第三方资源、日期转换、状态管理和持久化调用的业务插件；上述原生写入与主题验收边界不应被当成已完成。新库发布、npm 发布与索引远程推送均未执行。
