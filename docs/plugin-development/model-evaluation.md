# 8B 模型独立插件开发验收

状态：可执行的评测方案，2026-11-18，适用 API v1。尚未使用任何指定 8B 模型执行，本文件不宣称模型已通过。现有日历验证也不构成 8B 模型的能力证明。

## 1. 评测目标与输入

回答的问题：在给定公开契约、可运行模板和执行工具后，模型能否独立完成一个范围明确的插件，并保护用户数据。结果只适用于记录下来的模型和环境，不能推广到所有“8B DeepSeek”。

记录完整模型标识（含是否蒸馏）、量化格式、上下文上限、推理设置、运行器版本、初始提示词、输入文档提交号、宿主版本，以及工具权限。区分有文件/终端工具的代理与仅聊天输出代码的模型，后者需由操作者执行命令并原样反馈，执行成功不代表模型自己使用了工具。

允许输入：

- 插件指南 README.md、Demo 案例 demo-walkthrough.md。
- templates/mytools-notes 全部文件，包括测试与许可。
- 能力参考 04-plugin-spec.md，仅在需要时查阅；以指南中已实现契约为入口。
- 本页任务与公开验收标准。

不提供宿主内部实现、历史聊天、其他业务插件源码或现成的多便签实现。不需要联网、GitHub/npm 凭据或发布权限。评测在独立练习目录进行，不操作已有用户数据。文档链接均相对本目录。

若上下文较小，按“任务和约束 → 模板 → 按需 API → 失败日志”提供内容；每次记录补充材料。不要一次塞入全部宿主文档，避免把检索能力差异误当成编码能力差异。

## 2. 统一开发任务

基于单便签模板制作独立的“多便签练习”插件，身份 `mytools-notes-eval`，本地版本 0.1.0，不发布。

要求：

1. 显示便签列表，可新增、选择、编辑、保存与删除；删除前在页面内确认并可取消，不调用浏览器 confirm。
2. 每条便签有稳定唯一 id、非空标题、正文。标题 trim 后 1–60 个 UTF-16 码元，正文最多 20000；最多 100 条。允许空正文和同名标题。
3. 首次缺键显示空列表。新增、保存和删除成功后才提交新的持久化状态；失败保留原列表及待保存输入，允许重试。有未保存编辑时切换、新增、删除必须先确认放弃，不能静默丢失。
4. 新身份使用新键 `notes-eval.v1`，数据为 `{version:1,notes:[{id,title,text}]}`。校验全部字段、数量、长度、重复 id；未知版本或损坏数据禁止写入。不要读取或迁移模板的 notes.v1。
5. 仅使用 storage.get/set，不传 namespace，不使用 localStorage、IndexedDB、网络、剪贴板或直接 Tauri 调用。读失败不写，保存串行，重复 ready 不覆盖编辑。
6. 列表搜索按标题和正文做包含匹配，忽略拉丁字母大小写；只过滤视图，不改存储，不丢失未保存输入。搜索基于已保存便签；保存后刷新结果。零匹配时可清空搜索，仍可创建便签。无需 hostSearch。
7. 内容按纯文本显示。键盘能操作，嵌入与分离窗口、浅深主题、320px 宽窗口可用。明确提示手动保存、单窗口编辑限制；不宣称跨窗口合并。
8. 交付源码、MIT 许可、README、测试和 tgz；包不含测试、node_modules 或用户数据。报告实际执行结果及原生未验证项。

此任务故意超过模板的单文本模型，不能只改名或让原模板测试通过就算完成。模板允许作为起点，模型须新增符合多便签需求的测试。

复制以下文字并附上允许输入的材料；执行目录和平台由评测者填写，不附私人凭据：

```text
你要为 MyTools API v1 开发一个独立插件，完成 model-evaluation.md 第 2 节的“多便签练习”。
仅阅读提供的插件指南、Demo 说明、单便签模板和按需能力参考，不阅读宿主内部源码或其他业务插件。
先列出你将调用的 API、数据格式、失败保护和开发步骤，再在指定的独立目录实现。
每次只处理一个可验证阶段：包与入口；数据模型；存储与失败恢复；界面与确认；测试与归档。
不编造 API，不修改宿主，不发布 GitHub/npm，不自动接受原生权限。
遇到缺少的契约先指出具体问题；遇到测试失败根据真实日志修复，不通过删除断言来绕过要求。
最后报告执行命令、通过/失败数量、tgz 内容，以及尚未完成的原生验收，不把模拟桥接测试称为实机通过。
```

评测者在运行前固定时限与返修上限，例如 90 分钟、最多 3 轮完整失败日志反馈。只提供错误事实和文档位置，不提供实现代码。首次任务说明后的额外提示均记录；若给出实现指导，单独标为“人工辅导完成”。时限是评测预算示例，不是完成时间承诺。

## 4. 自动检查与独立复核

在交付目录执行 `npm test`、`npm pack --dry-run`、`npm pack`。解包实际 tgz 到临时目录，检查 plugin.json、相对资源引用、版本与文件白名单，随后把同一 tgz 安装到宿主。

除了模型自己的测试，评测者另行检查以下场景；测试应调用实际业务代码，不能只断言模拟函数本身：

| 场景 | 必须观察的结果 |
|---|---|
| 缺键 null | 空列表，不自动覆盖其他键 |
| 读取拒绝或失败 | 禁止编辑写入，显示原因，可重试 |
| 未知版本、错字段、重复 id、超量/超长 | 拒绝写入，原数据保留 |
| 新增、编辑、删除时保存失败 | 已保存状态不变，草稿保留，可重试 |
| 慢保存，连续点击或重复 ready | 不产生并行覆盖，不重载草稿 |
| 取消删除或取消放弃编辑 | 没有写入，列表和草稿不变 |
| 搜索、无结果、清空搜索 | 只改变显示，不删除便签，不丢草稿 |
| 重建插件实例 | 从同一个模拟存储恢复正确列表 |
| 中文、多行、emoji、HTML 文本 | 计数遵循约定，内容不会变成可执行 HTML |
| 归档 | 包内资源完整，安装身份唯一，无测试及开发依赖 |

故障注入用于模拟测试；不要靠损坏真实用户数据制造故障。检查是否新增未声明能力、绕过宿主存储或削弱测试断言。静态搜索只能辅助审查，不能替代行为验证。

## 5. 原生验收

在干净测试身份下安装实际 tgz，人工完成：

1. 搜索打开；分别检查读取拒绝、允许后重试、写入拒绝和允许后的保存。若权限已记住，使用宿主权限界面或全新测试身份，不手工修改用户数据库。
2. 新建两条便签，编辑一条、取消一次删除、确认另一次删除；重启宿主后核对结果。
3. 有草稿时尝试切换、创建和删除，分别取消及确认放弃；搜索和清空搜索不应丢草稿。
4. 嵌入/分离、浅深主题、窄窗口、键盘操作。输入 HTML 测试字符串应保持普通文本。
5. 记录权限提示、界面错误和保存结果。未经操作的项标“未验证”，不能补写“通过”。

多窗口同时写入、云同步、系统级磁盘故障不在本任务验收范围；界面必须明确其限制。

## 6. 评分与结论

| 项目 | 分值 | 主要依据 |
|---|---:|---|
| 独立包、身份、资源和实际安装 | 15 | 归档检查与宿主识别 |
| 新增/选择/编辑/删除/搜索和输入边界 | 20 | 行为测试与手动操作 |
| 版本校验、失败保护、草稿与串行写入 | 30 | 独立故障注入测试 |
| 公开 API、最小权限与安全显示 | 15 | 调用记录、源码审查和原生操作 |
| 响应式、键盘、主题 | 10 | 原生检查 |
| 可复核测试、说明与真实结果报告 | 10 | 命令日志和验收记录 |

读失败覆盖数据、未知版本继续写入、静默丢草稿、执行用户 HTML、绕过公开 API、虚报实测、擅自发布，任一出现即不通过，不用总分抵消。

- 自动检查达标但原生未完成：结论只能写“自动阶段通过，原生待验收”。
- 原生全部完成、无否决项、至少 85 分，且未提供实现指导：本轮“独立通过”。
- 达标但接受实现指导：记录“辅导后通过”及人工改动。
- 不达标：记录“未通过”、失败点和所需文档改进，不把失败直接归因于参数规模。

若要评估稳定性，至少用 3 个全新会话重复，保留所有结果，不只展示最好的一次。相同模型的不同量化、工具或上下文配置分开统计。
