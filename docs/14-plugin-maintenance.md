# 插件故障修复与日历功能核查

状态：2026-11-19 本地修复，未推送 GitHub、未发布 npm。版本号不代表远端发布；下文的源码状态也不代表旧安装包已自动更新。

## 原因与改动

| 用户现象 | 代码与安装内容核查 | 本地修正 |
|---|---|---|
| 计算稿纸导出出现 dialog confirm ACL 错误 | 本机旧插件仍使用浏览器确认及 a.download，清单缺少 fs.exporttext；仓库已有公开导出 API 和网页确认实现。当前宿主源码使用网页内授权队列，没有直接调用 dialog confirm | 将插件源码标为本地 0.1.1 并打包，验证公开导出、取消与拒绝路径。需安装实际新包；旧宿主若在授权时仍调内部 confirm，则须重建宿主 |
| 剪贴板不能展示图片 | 原后台轮询只调用 read_text，图片从未进入历史；界面其实已有 data URL 预览 | 增加按剪贴板序号读取图片、PNG 编码、kind 分类与数据库兼容迁移，限制图片容量；插件按 kind 预览与复制，不误把图片 URL 文本当图片 |
| 颜色助手与屏幕取色器按钮无响应 | 原主按钮只依赖浏览器 EyeDropper，WebView 不支持时无法取色；颜色助手未声明已有宿主 screen.pickcolor 能力 | 主按钮统一使用宿主延时取色和能力声明，不再调用可能一直不响应的 EyeDropper；先授权，再倒计时 3 秒读光标像素；Esc 取消，错误可见，结束恢复按钮；不提供浏览器放大镜 |
| Markdown 预览和双栏无变化 | 操作隐藏旧面板；实际 md-editor-v3 2.11.3 在 setup 时固定模式参数，单改 previewOnly 属性不足 | 按所选模式重新挂载实际编辑器，保留文档，控制真实预览/源码/双栏；显示源码模式按钮。模式切换可能重置组件撤销栈和光标，不承诺保留撤销历史 |

剪贴板旧库添加 kind 字段，历史文本按 text 保留；PNG data URL 单条不超过 4 MiB，图片内容合计不超过 32 MiB，输入不超过 1600 万像素。优先保留置顶图片；容量不足时拒绝新图片或淘汰旧未置顶图片。只改变新宿主启动后的采集能力，无法补回过去未记录的图片。事件通知不再广播完整剪贴板内容，只通知变化。权限仍通过公开能力处理，不扩大插件 Tauri ACL。

## 日历源码检查结论

检查对象为独立仓库 mytools-calendar 的源码 0.1.1；本机已安装的 plugin.json 仍为 0.1.0。当前 npm 稳定版 0.1.0 与源码新增功能不能混为一谈。

| 功能 | 源码 0.1.1 状态 | 具体边界 |
|---|---|---|
| 导出全部 Todo | 已有 | Markdown、Excel XML（.xml）和 JSON，不受当前日期或筛选条件影响；不生成二进制 .xlsx |
| 部分导出 | 没有 | 没有按所选事项、日期范围或当前筛选导出的入口；exportTodos 使用全部 tasks |
| JSON 导入 | 已有 | 先校验文件和预览，再确认合并；取消不写入，保存失败不提交 |
| 全部覆盖导入 | 没有 | 合并逻辑保留原有其他 ID，不执行全量替换 |
| 增量添加 | 有合并能力，但不是严格“只新增” | 新 ID 新增、相同 ID 被导入内容覆盖、标签并集；重复导入不产生重复 ID |
| 选择添加 | 没有 | 没有勾选导入事项的列表或选择导入模式 |
| 日常 Todo 管理 | 已有 | 按日新增、编辑、完成/未完成、确认删除，按标签及状态筛选 |
| 统一 Todo 管理页 | 没有 | 无跨日期汇总检索、批量选择操作等独立管理界面 |
| 标签管理 | 已有 | 搜索、多选删除、改名、迁移关联标签；不删除 Todo |

证据：[导入导出逻辑](../../plugins/mytools-calendar/transfer.mjs)、[交互入口](../../plugins/mytools-calendar/app.mjs)、[页面](../../plugins/mytools-calendar/index.html)、[传输测试](../../plugins/mytools-calendar/tests/transfer.test.mjs)与[界面测试](../../plugins/mytools-calendar/tests/ui.test.mjs)。本次只核查这些功能，没有擅自增加覆盖、部分导出或选择导入。

另发现 Windows Git 换行转换使 vendor/lunar.js 的文件哈希与记录不一致。已恢复已提交的原始字节（SHA-256 与 THIRD_PARTY.md 一致），并添加 .gitattributes 禁用该第三方文件的文本转换，没有修改其算法或许可证。

## 生效方式与验证边界

五个修复插件的源码版本为本地 0.1.1，商店索引仍指向已发布版本，不自动改为未发布包。插件需通过开发者页面安装新 tgz，关闭重开后加载；仅改源码不会改变已安装插件。

剪贴板后台与旧宿主授权流程需要重建、替换宿主程序后才能生效。构建必须保留 GNU 工具链、Common-Controls manifest、WebView2Loader.dll 和发布路径依赖检查。不能把前端构建通过说成 Windows 宿主已构建。

DOM 测试使用模拟宿主 API 验证，包含真实 vendored Markdown 编辑器组件。原生保存对话框、实际系统图片采集/图片回写、桌面光标采样与多显示器仍须在实际修复后的宿主验收；测试不读取或覆盖用户 Todo、剪贴板库或插件存储。最终执行结果以本次交付报告为准。

## 2026-11-20 本地后续修复

上文日历表为最初核查记录。后续已在本地安装日历 0.2.0，补充部分导出、增量/勾选/合并/覆盖导入和跨日期 Todo 管理；相关改动已纳入本次发布，可安装版本以插件索引和 npm 为准。

宿主现已完成 GNU 发布构建并可正常启动；旧文本历史可通过新 kind 字段兼容读取。新增处理资源管理器 Ctrl+C 的单个本地 PNG 文件：通过 CF_HDROP 读取单文件路径，再按图片内容加入历史。文件路径不作为图片内容写入；只接受本地磁盘 PNG，输入文件至多 4 MiB、1600 万像素，输出沿用 PNG 3 MiB/单条 data URL 4 MiB 和图片历史总量 32 MiB 限制。多选文件、网络路径和其他格式暂不转换为图片历史。剪贴板本身保持文件复制格式，不改成位图。

本地搜索源码已有空查询不发起搜索、清空时取消旧结果的行为，但之前安装的独立插件还是旧文件。此次打包本地 0.1.1 以同步安装内容；重建宿主不会自动同步插件仓库。

新增测试覆盖复制 PNG 文件读取、损坏文件、超大文件/像素拒绝；实际资源管理器复制和图片再次粘贴仍须本机验收。后端测试/Clippy 与 Tauri 正式构建的执行结果记录在本次本地交付中。
