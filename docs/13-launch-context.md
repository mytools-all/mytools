# 面板启动上下文

> 状态：首期实现。相关文档：[插件规范](./04-plugin-spec.md)、[工具交互](./12-tool-interactions.md)。本文定义面板如何向插件转交用户操作上下文，以及后续来源的扩展边界。

宿主负责捕获、保存和交付上下文，插件只接收用户通过面板转交的数据。插件不需要自行监听全局鼠标、模拟复制或反复轮询剪贴板。

## 启动流程

1. 中键释放时记录前台窗口，在后台捕获上下文，再显示面板，避免面板获得焦点后丢失来源。
2. Windows 资源管理器窗口通过 Shell 的 SelectedItems 读取所选文件、文件夹，最多 1000 项。系统适配在 infrastructure，3 秒超时，不阻塞鼠标钩子。
3. 同时捕获剪贴板图片或文本。图片最多 1600 万像素、编码后的 PNG 最多 3 MB；文本最多 1 MB。不读取任意应用里的选中文字，不模拟 Ctrl+C。
4. 点击插件后，将快照绑定到新窗口和插件身份；只允许面板窗口发起转交。普通打开插件不会接收此上下文。
5. 生命周期 ready 中的 `launchContext: true` 仅表示从面板启动，不包含实际数据。插件声明 `context.read`，经过现有会话和能力授权后请求自己需要的类型。
6. `context.read` 只消费一次，120 秒过期；重新唤出替换面板快照，关闭窗口清理待交付数据。数据只保存在内存，不写入配置、日志或插件索引。

```js
window.mytools.onPluginReady(async (env) => {
  if (!env.launchContext) return;
  const context = await window.mytools.call('context.read', { types: ['files'] });
  if (context?.files?.length) importFiles(context.files);
});
```

文件条目与 `fs.pickfiles` 格式一致：`path/name/directory/size/modified`。导入时验证条目，排除符号链接和特殊文件，并按已有文件选择流程授权所在目录。插件仍须预览、确认后执行重命名。

图片结构为 `{ mime: 'image/png', dataUrl }`。OCR 仅载入预览，用户点击识别后才调用外部识别服务。图片不通过生命周期广播给所有插件。

## 搜索框与窗口

插件清单的 `hostSearch` 声明占位文字；主窗口中 `env.hostSearch === true` 时隐藏自己的输入框，通过 `onSearch` 接收输入。独立窗口的该值为 false，保留插件自己的输入框。

插件中心同样复用顶部搜索框，商店和已安装使用独立查询状态，不触发启动器应用搜索。分离后的插件中心使用原生窗口边框及页面内搜索框，四个页面共用一个独立窗口。

## 后续扩展边界

新增来源（拖放、命令行、浏览器选区等）接入宿主采集层，仍交由统一上下文存储与能力交付，不在各插件中增加全局采集代码。新增类型需同时定义大小限制、来源及读取权限；可进一步增加清单中的接受类型声明，用于面板入口推荐。

当前不支持桌面图标选择、任意应用文本选区及截图工具尚未复制到剪贴板的图片；不自动识别、不自动更名。没有合适数据时，插件保留手动选取、拖入和粘贴入口。
