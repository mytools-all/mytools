# 主程序与插件更新

状态：实现说明，适用于 0.2.0；正式在线安装仍需发布后验收。

主程序 0.2.0 增加更新设置。偏好设置中的“常规选项”保存更新方式，并显示 Windows 实际开机自启状态。开启自启后登录到托盘，不弹主窗口。Windows 自启通过当前用户的登录任务计划实现，使用 InteractiveToken 和 LeastPrivilege，不保存密码。开关读取任务启用状态、登录触发器和启动目标；只管理带本程序标识的当前用户任务，不创建注册表启动项或启动文件夹快捷方式。

主程序每次启动自动检查一次，默认只提醒；可禁止自动检查，仍保留手动检查。自动下载需要正式发布提供签名更新包，下载并校验后等待用户保存编辑内容、确认安装和重启。检查失败不会显示“已经是最新版”。较新的本地版本也不会被降级到旧的公开版本。

“关于”与“常规选项”共用后端检查状态。检查公开的 GitHub Release，不调用 GitHub CLI，也不要求用户登录 GitHub。现有 v0.1.0 没有更新清单，仍能检查版本，旧格式的新版本仅提供前往发布页的入口。

## 生成更新包

使用 Windows GNU 工具链和项目锁定依赖。更新采用 Tauri updater 的签名校验；公钥在 `src-tauri/tauri.conf.json`，私钥由维护者单独保管，不进入源码、发布附件或日志。备份私钥；更换公钥需要已有版本能够信任新密钥的迁移安排。

在项目根目录运行：

```powershell
pwsh -NoProfile -File scripts/build-update.ps1 -SigningKey <本机私钥绝对路径> -OutputDirectory <输出目录>
```

加密私钥可通过 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 环境变量提供密码，脚本不打印密码或私钥。输出 NSIS 安装包、`.sig`、`latest.json` 和 `SHA256SUMS.txt`。只生成附件，不提交、不发布。安装包位于 `release-artifacts/` 时应保持忽略。

验收通过后，将四类文件上传到同一正式 Release（标签 `v<package.json版本>`）。版本必须同时匹配 package.json、Cargo.toml、Release 标签及清单。清单中的地址固定到该标签，不能指向其他仓库。不要上传私钥。GitHub 发布需要维护者授权，和软件使用者的检查更新无关。

当前版本只支持 Windows x64。尚未发布带签名的新版本时，无法完成跨正式版本的在线安装验收，不能把本地构建通过描述为线上更新已经验收。

## 插件商店

每个插件中心窗口会话首次进入时先展示缓存，再后台检查一次，不重复发出并行请求。商店不再放检查更新或全部更新按钮；需要重试检查可在“已安装”进行。

“已安装 → 可更新”支持单个更新、选择更新、全选当前搜索结果及更新全部。更改搜索条件或分类会清空选择，避免更新不可见项。更新全部始终指全部可更新插件。安装串行进行，失败后继续其他插件并汇总原因。

更新中的插件不能新开会话，已打开的插件也不能覆盖安装；先保存并关闭对应插件，再重试。更新保持现有插件数据、启用状态及权限记录。主程序更新方式不改变插件策略。

## 自动生成发布草稿

推送与源码版本一致的版本标签（如 v0.2.1）后，CI 必须先通过前端、Rust、核心覆盖率、构建和界面测试，再签名构建 NSIS、生成 ZIP 和更新清单、上传到 GitHub Release 草稿。仓库 Secrets 需要 TAURI_SIGNING_PRIVATE_KEY，加密密钥另需 TAURI_SIGNING_PRIVATE_KEY_PASSWORD。草稿不会成为公开最新版；维护者核对附件后手动点击 Publish release。主程序不发布 npm。
